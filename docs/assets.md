# 3D assets: pipeline, conventions, original camera, sprite check

Milestone M2 replaces sprites by 3D models. Every model is a Python script that Blender runs
headless to rebuild its glTF file; nothing generated is committed. The sprite check renders a
model through the game's original camera and scores it against the original sprites.
Tracking: #176; pipeline #162, sprite check #165. How the game draws the models (settings,
where it looks for them, the camera as a matrix): [rendering-3d.md](rendering-3d.md).


An asset script defines `TYPE` (the `NAME` of its `.MD`, or `LIST:INDEX` for a map object
such as `TREELIST:104`; optional), `CHECKS` (optional: one `acr model-check` argument string
per check, e.g. `["--anim STAND", "--anim STANDLO --sections 2"]`; each also gets its own
reference, passed to the script as `ctx.refs[<label>]`, label = the values joined by `-`) and
`build(ctx)`:
`ctx.root` is the root node (an empty at the ground point, named after the script),
`ctx.ref` the sprite reference (`acr_assets.Reference`, see below) or `None`. Scripts in other
folders (e.g. `assets/blender/humans/`) can use the helpers by putting `assets/blender/lib`
on `sys.path`; `build.py` does this for every asset.

## Running

Blender 5.2 is found through `$BLENDER`, then `C:\Program Files\Blender Foundation\Blender
5.2\blender.exe`, then `blender` on the `PATH`.

```sh
# all assets, or the named ones; colours from the sprites when the game folder is known
cargo xtask assets [incdo1 ..] [--game-dir DIR] [--compress none|meshopt|draco] [--blend]
# ... and the sprite check for each asset with a TYPE
cargo xtask assets incdo1 --game-dir "C:\path\to\American Conquest" --check

# the pieces, by hand
acr model-ref   <game-dir> IncDo1 out/ref                 # ref.json + ref_<k>.png
blender -b --factory-startup --python assets/blender/build.py -- assets/buildings/incdo1.py \
        --out out/incdo1.glb --ref out/ref/ref.json
acr model-check <game-dir> IncDo1 out/incdo1.glb out/check [--min-iou 0.85]
acr gp-frame    <game-dir> INCDO1.GP 5 frame.png [--no-shadow]   # one frame, prints its origin
```

`ACR_GAME_DIR` works instead of `--game-dir`. Without a game folder the assets build with
their flat colours. `--blend` also saves the scene next to the `.glb` for inspection.

## Units and axes

- **Scale: 1 world pixel = 1/30 m (30 px per metre).** A standing musketeer (`EngM18`,
  `#STAND`) reaches 45–47 screen pixels above his ground point (the musket further), which is
  52–54 world pixels of true height (÷ cos 30°, below); a man with a hat is about 1.8 m. Buildings in the original
  are drawn smaller than real ones (the Inca hut `IncDo1` is 6.2 × 3.2 m); models keep the
  sprite size so that they fit the map.
- **Blender:** metres, +X east (game x), +Y north (game −y), +Z up. **glTF** (+Y up, the
  exporter converts): +X east, +Y up, +Z south, i.e. glTF x, z are the game's x, y in metres.
- **Origin** = the object's ground point: the position the game stores for the object, at
  terrain height. For units and buildings that is the point a sprite frame is drawn relative
  to (`USERLC … dx dy` plus a building's `LOCATION`).
- **Facing:** models face south (Blender −Y, glTF +Z): `RealDir` 64, stored direction 0.
- **Naming:** root node = asset name (`incdo1`), parts `incdo1.<part>`, attachment points
  `socket.<name>` (empties; e.g. `socket.roof` for fire and smoke). Custom properties on the
  root become glTF extras: `acr_asset`, `acr_type`, `acr_pixels_per_metre`.
- Measurements on sprites are world pixels (`acr_assets.shapes` takes game x, y and true
  heights in world pixels and converts them).

## The original camera

The game projects a world point (x, y) at height h as (`docs/formats/terrain.md`)

```
screen x = x            screen y = y / 2 − h
```

with the height in screen pixels. This is an orthographic camera looking north and down by
the elevation e with sin e = 1/2, **e = 30°** (2:1 dimetric). A true orthographic camera at
30° shows a vertical length z as z · cos 30°, so the game's heights in screen pixels (terrain
`SURF`, sprite offsets) are true heights × cos 30° = 0.866. With the camera basis (Blender
coordinates, metres; s = 1/30 m per pixel)

```
right   = (1, 0, 0)
up      = (0, sin e, cos e)   = (0, 0.5, 0.866)
forward = (0, cos e, −sin e)  = (0, 0.866, −0.5)       (view direction)
```

a point p (model space) of a model at canvas pixel `anchor` facing `RealDir` d lands at

```
yaw(d) = −(d − 64) · 2π / 256         (rotation about +Z; 64 = south = 0)
q      = Rz(yaw(d)) · p
canvas = anchor + (q · right, −q · up) / s
```

Check: ground point (x, −y)·s → (x, y/2); height z → −z · cos 30° / s. Pixel (i, j) covers
[i, i+1) × [j, j+1) and the anchor is a pixel corner, like a GP frame origin.

**Blender camera** (`acr_assets.camera.original_camera`): `ORTHO`, rotation (60°, 0, 0) XYZ
(X = 90° looks north, minus the 30° elevation), `ortho_scale = max(W, H) · s` with
`sensor_fit = AUTO`, resolution W × H at 100 %, and location

```
location = right · (W/2 − ax) · s + up · (ay − H/2) · s − forward · 200 m
```

because Blender maps the camera centre to the canvas centre. The model turns, not the camera
(`yaw` above); free rotation in the game is the inverse.

**Directions** (`docs/simulation.md`, "Directions and sprites"): GP frame `f · R + k` is
frame f in stored direction k of R. The direction a stored picture shows
(`stored_direction`, Rust `acr model-ref`, Python `conventions.stored_direction`) is the
centre of the sector that `acr_render::scene::sprite_direction` maps to k unmirrored:

| stored directions R | RealDir of k | |
|---|---|---|
| 1 (buildings, map objects) | 64 | the fixed view |
| odd (9 for units, 65 ships) | 64 + 128 k / (R − 1) | 9: 64 south, 128 west (k 4), 192 north (k 8) |
| even | 64 + 128 (k + ½) / R | half a sector off |
| `FULLROTATION` (16, cannon) | 64 + 256 k / R | all around, never mirrored |

The east half of odd/even counts is drawn mirrored around the ground point and has no
pictures of its own. Quirk: north (k = R − 1 of an odd count) is only ever drawn mirrored
(sector i = 0), which shows only on asymmetric pictures; the check compares the stored
picture unmirrored with a render at 192.

Both directions of the mapping are unit-tested: Rust (`acr-tool`, against
`sprite_direction` itself) and Python (`assets/blender/tests`, also the camera placement
against the generic orthographic mapping).

## Sprite reference (`acr model-ref`)

For an object type and animation (default: `#STANDLO` for buildings, `#STAND` for units; a
unit's frame `--step`) it draws, per stored direction, all parts of the animation (a
building's back and front frames) at their offsets onto one canvas, **without shadow layers**
(encodings 5, 0x26, 0x27: a model casts its own) and with the pack's palette. The canvas is
the union of all views plus 16 px; `ref.json` holds the canvas size, the anchor (ground
point) and per view `k`, `dir` (RealDir) and the image.

## Colours from the sprites (`acr_assets.project`)

Every face takes its colours from the view that sees it most frontally among those in which
it is not hidden (ray casts from its centre and near its corners towards the camera). The
views go side by side into one atlas texture (`sprite` UV map, nearest filtering);
transparent pixels are filled from their neighbours so edges do not turn black. Faces no view
sees get a flat material in the mean colour of their object's visible faces. Limits: the
sprites carry the original lighting (used as albedo, so lighting is doubled in a lit
renderer); a face is visible or hidden as a whole; the mirrored half of unit directions adds
nothing; a model seen from the side of a building's single view shows flat colours there.
Building models therefore hold up from all sides in shape but not yet in texture.

## Realistic surfaces for buildings (`acr_assets.surfaces`)

A realistic look matters more than matching the sprites (user decision, #214): buildings use
shared procedural materials instead of the projection. `surfaces.py` generates tileable
256-pixel colour textures with their shading baked in, so they read under the game's simple
Lambert light:

| Kind | Look | Metres per tile |
|---|---|---|
| `logwall` | horizontal logs, rounded shading, grain, weathered tops, dark chinking | 1.6 |
| `bark` | stakes and log piles: vertical fissures, lichen | 0.35 |
| `shingles` | wooden shingles in staggered rows along the eaves, row shadows, a little moss | 1.4 |
| `slate` | darker, finer shingles (stone house) | 1.2 |
| `timber` | hewn beams and boards: grain, cracks, weathering | 1.0 |
| `stone` | fieldstone masonry with mortar joints | 1.8 |
| `rubble` | larger loose stones | 0.8 |
| `earth` | trodden earth, pebbles, grass | 4.0 |

`surfaces.aligned_uv` maps each face along its own axes: u along the face's horizontal
direction (a roof's eaves, a wall's length), v up its slope, ground axes for flat faces; so
shingle rows follow the eaves and bark runs up the stakes whatever the building's angle.
An asset picks the kind by part name (`SURFACES` rules, first match wins, e.g.
`("roof", "shingles")`), and `surfaces.apply` gives every mesh its material. Each kind's
material is made once per build and shared by all states and parts.

For `EngKre` this replaced the per-state sprite atlases: the build takes 8 s instead of
2 min 18 s, the file is 2.6 MB instead of 6 MB, and the back walls and far roofs look like
the front in the free camera (#202). `PROJECT = True` in the script brings the projection
back. The sprite check stays a sanity check for size and placement only.

## Sprite check (`acr model-check`)

`acr model-check <game-dir> <TYPE> <model.glb> <out>` writes the reference, runs
`render_views.py` (Workbench, flat lighting, texture colour, no anti-aliasing, transparent
film, view transform *Standard*; the model is rotated for each stored direction) and compares
`render_<k>.png` with `ref_<k>.png`:

| metric | definition |
|---|---|
| IoU | silhouettes = alpha ≥ 128 (the 25 % translucent layers do not count); intersection / union |
| colour diff | mean absolute RGB difference (0–255, mean of the channels) where both are solid |
| anchor shift | the integer shift (±24 px) of the render that maximises the IoU, and that IoU; (0, 0) when the model stands where the sprite does |
| area | solid pixels of sprite and render |

Outputs: `report.md`, `report.json`, `side_<k>.png` (sprite | render | silhouettes: grey
both, magenta sprite only, cyan render only). `--min-iou X` fails the command below X, for
use as a regression test. The tool is Rust (it decodes the GP frames and reads the `.MD` with
`acr-formats`, as the viewer does) and only the rendering runs in Blender; nothing in it needs
Blender at compile time, so CI stays independent of Blender.

### Proof: `IncDo1` (Inca hut)

`assets/buildings/incdo1.py`: plinth, wattle walls, stone corner pillars, posts, thatched hip
roof, ridge pole and net frame. Its plan was fitted to the sprite silhouette (`#STANDLO`,
frames 4 + 5 of `INCDO1.GP`).

| colours | IoU | colour diff | anchor shift | `.glb` |
|---|---:|---:|---|---:|
| from the sprite | 0.903 | 3.2 | (0, 0) | 131 KB |
| from the sprite, `--compress meshopt` | 0.903 | 5.0 | (0, 0) | 141 KB |
| flat (no game folder) | 0.903 | 47.0 | (0, 0) | 31 KB |

The colour difference of 3.2 with projected colours shows that the camera reproduces the
sprite to the pixel (a half-pixel error gives ~20). The remaining silhouette error is detail
the primitives do not have: the ragged thatch edge, rubble at the wall foot, the open door
and the sparse net. A crude three-cylinder probe of the musketeer `EngM18` (not committed)
checks all 9 directions with anchor shifts of 0–1 px horizontally and 2–4 px vertically (the
sprite's feet reach below the ground point).

## Export and compression

`acr_assets.export.export_glb`: glTF 2.0 binary, +Y up, modifiers applied, custom properties
as extras, no cameras or lights, images as PNG (packing turns opaque base colours into
JPEG, below). Blender 5.2's exporter also offers:

- **meshopt** (`EXT_meshopt_compression` or `KHR_meshopt_compression`, built in):
  `--compress meshopt`;
- **Draco** (`KHR_draco_mesh_compression`, built in): `--compress draco`;
- images as JPEG or WebP (`EXT_texture_webp`), but **no KTX2/Basis**: that needs an external
  tool (`gltfpack -tc`, `toktx`), which is not installed and not downloaded by the build.

**Packing (#199).** Without `--compress`, `acr_assets.gltf_pack` rewrites the exported
file (pure Python, `ACR_GLTF_PACK=0` skips it; what it did lands in `stats.json` `pack`),
all in core glTF 2.0 types the renderer reads, no extension required:

- `WEIGHTS_0` as normalised bytes summing to 255; `COLOR_0`, `_GORE`, `_FACE`, `_WIND` as
  normalised bytes; `TEXCOORD_n` in 0..1 as normalised shorts. `_PART` and `_LIMB` stay
  float (a vertex attribute element is 4-byte aligned anyway); positions, normals and
  morph targets stay float (that needs `KHR_mesh_quantization`); dense morph targets become
  sparse where smaller;
- clip rotations as normalised shorts; sampled linear channels keep only the keys that
  interpolation does not reproduce within 2e-4 rad / 2e-4 m; constant channels keep their
  ends, and drop out when they equal the node's own transform (the exported STAND pose the
  renderer falls back to) while another channel keeps the clip's length;
- opaque base colours as JPEG, quality 88 (`JPEG_QUALITY`, Blender's libjpeg writer,
  4:2:0 chroma; `export.encode_jpeg`): an image goes JPEG only when every material that
  uses it takes it as `baseColorTexture` with `alphaMode` `OPAQUE`, its alpha is all 255
  and the JPEG is smaller than the packed PNG (1×1 swatches stay PNG). Normal,
  metal-roughness, occlusion and emissive maps, leaf cards and hair (`MASK`/`BLEND`) stay
  PNG. `ACR_GLTF_JPEG=0` keeps every image PNG; `stats.json` `pack.jpeg` is
  `[images, PNG bytes, JPEG bytes]`;
- the other PNGs re-encoded losslessly (ancillary chunks dropped, constant opaque alpha
  removed, an indexed PNG when the image has at most 256 colours, adaptive filters, zlib 9);
  identical images, views and accessors stored once.

The renderer reads custom attributes of any component type (`model.rs` `custom_f32`) and
decodes PNG and JPEG images (`decode_png`, `decode_jpeg` with `zune-jpeg`).

| File (packed, 2026-10-24) | PNG only | with JPEG | JPEG images |
|---|---|---|---|
| `engm18.glb` | 3.27 MB | 2.16 MB | 8 (1.74 → 0.40 MB) |
| `engd18.glb` | 6.99 MB | 3.62 MB | 18 (5.08 → 0.67 MB) |
| `delkri.glb` | 2.39 MB | 1.50 MB | 12 (1.53 → 0.36 MB) |
| `engcen.glb` | 2.10 MB | 0.96 MB | 1 (1.50 → 0.21 MB) |
| `conifer.glb` | 2.24 MB | 1.80 MB | 1 (bark; leaves and normals stay PNG) |
| `map_t452.glb` | 1.09 MB | 0.87 MB | 1 (normal map stays PNG) |

(Built on the render VM, `ACR_GLTF_JPEG=0` against the default; the swatch rule, added
after, takes off about 1 KB more.) In-game close-ups (face, uniform, building, ruin, tree;
`ACR-analysis/small-gltf/jpeg/png_vs_jpeg.png`) differ by 43–63 dB PSNR with no visible
artefact; the largest differences sit on the eye whites and the coat's red, where 4:2:0
chroma halves the colour resolution. GPU memory does not change: both decode to RGBA8.
What is left of EngM18 is meshes and clips (about 1.7 of 2.16 MB). An 8-bit palette for
the remaining PNG atlases would halve them but is lossy (mean error 0.2–0.3, max 40 levels;
2–3 on normal maps), and half resolution quarters them; neither is applied.

For small models like `IncDo1` the texture dominates and meshopt makes the file larger
(141 vs 131 KB; its UV quantisation also moves the colour difference from 3.2 to 5.0). The
default stays uncompressed until the in-game renderer (#163) decodes meshopt; KTX2
textures are a follow-up together with it.

**States.** Node groups carry extras the renderer and the check read: `acr_state` (the
animation that shows them: `STANDLO`, `BUILDLO_2`, `DEATHLIE1`, a list for several) and
`acr_section` + `acr_section_state` (an `ADDSECTION` part, drawn with `STANDLO`). `acr
model-ref --sections S` draws every section in state S after the animation's parts, as a
finished building does; `render_views.py` plays the clip named after the reference's
animation and shows only the matching states.

## Ships and guns from downloaded bases (#287)

Ships and artillery start from professional base models (`assets/LICENSES.md`), kept
**outside the repo** in a folder of extracted sources named by `ACR_SOURCES`
(`<source>/<name>/...`; locally e.g. `D:\ACR-models\extracted`, on the render VM
`/home/claude/sources`, which `blender_vm.py` passes on). `acr_assets.vessels` imports a base,
keeps only its base colour (textures shrunk to 1024 px and re-packed as PNG), decimates it,
and rigs it with rigid bones; `acr_assets.ships` builds the sailing ships.

| Asset | Base | Size | Triangles | Clips |
|---|---|---|---:|---|
| `ships/shpfregat.py` (`ShpFregat`) | Poly Haven `dutch_ship_large_01` | 40 m | 27.8k | `STAND`, `MOTION_L/R/LB/RB`, `ATTACK`, `DEATH`, `DEATHLIE1` |
| `ships/shpsanta.py` (`ShpSanta`) | Poly Haven `dutch_ship_large_02` | 34 m | 23.8k | same |
| `ships/shppinta.py` (`ShpPinta`) | Poly Haven `dutch_ship_medium` | 28 m | 19.7k | same |
| `artillery/artpus.py` (`ArtPus`) | rivetech's barrel (CC-BY) on a scripted field carriage, 4 crew, ammunition chest | barrel 2.5 m | 31.8k | `STAND`, `GUN_PUSH`, `CHEST_CARRY`, `TRAIL_LIFT`, `TRAIL_WALK`, `DEPLOY`, `ATTACK`, `DEATH`, `DEATHLIE1` |

- **Ships** face south with the waterline at the ground point; the afloat hull is cut 0.25 m
  below it (the game draws water as a tint on the ground, nothing would hide the keel). Bones:
  `hull` (rocking, heel, sinking) > `intact` (hull, rigging) > `sail<k>` (each sail at its
  centre: slack at anchor, full under way) and `wreck` (a charred, uncut copy of hull and
  masts). The `.MD` gives ships one frame per direction, so their clips run on the **game
  clock** (`acr_clock = "world"` on the root): looping while afloat, from the death on while
  sinking (12 s: burnt at once, lists to port, down by the bow; the terrain depth hides what
  goes under, mast tops stay above like a wreck in shallows).
- **The field cannon** keeps the sprite clock (frame counts of `ARTPUS.MD`: `MOTION_L0` 36,
  `ATTACK4` 420 with the shot at frame 29, `DEATH` 73): wheels roll one turn per motion cycle;
  the shot throws the piece 0.9 m back with a muzzle kick, it is run back into battery by
  frame 400; destroyed, a wheel is smashed, the barrel thrown off and the carriage charred.
  The crew (`acr_assets.guncrew`, below) works the drill in the same clips.
- **The gun crew** (#287): four artillerymen on skeleton H joined into the gun's armature
  (bones `c0.`..`c3.`, the riders' idea: one model, one clip set). Blue coat with red
  waistcoat, buff breeches, black gaiters, tricorn (the Royal Artillery and the French
  artillery both wore blue; one coat for every nation for now, palette colours, no sprite
  projection, no faces). Kit: c0 the sponge/rammer staff, c1 a leather cartridge bag on
  the hip, c2 a handspike, c3 the linstock with its match. Stations (gun facing -Y, muzzle
  at y -1.4): c0/c1 either side of the muzzle outside the wheels, c2 at the trail end, c3
  right of the breech outside the wheel's recoil path.
  - `ATTACK` (420 frames): c2 traverses the trail with the handspike (0..18), everyone
    stands clear (20..26), c3 puts the linstock on the vent at frame 29 = the gun's shot
    and flinches back from the recoil; c0 sponges in front of the recoiled muzzle
    (64..130), c1 takes cartridge and ball from his bag and puts them into the muzzle
    (135..170), c0 rams twice (178..235), c2 thumbs the vent and primes it (58..270); from
    300 c0/c1 push on the wheels and c2 on the trail as the piece runs back into battery
    (400), and all go back to their stations (419).
  - `MOTION_L/R`: c0/c1 push on the wheels, c2 on the trail, c3 walks alongside, three
    strides per wheel turn. `STAND`: at their stations, ready. `DEATH`: all four fall
    where they stand (staggered by 2 frames), lying in `DEATHLIE1`.
  - Limits: between stations the men glide (no steps keyed on those moves), poses are
    hand-set (no IK on the staffs: hands and staffs only roughly meet), the four share the
    gun's `acr_machine` root (no blood or rot on them).
- Roots of both carry `acr_machine = true`: no blood pools, sprays, wounds, corpse piles or
  rot (decay), and no sinking into the ground (`docs/rendering-3d.md`).

## Generated buildings and ships (`acr_assets.genbuild`)

Models generated by Tripo and Meshy from one sprite view each (buildings: the isometric
`#STANDLO` picture; ships: the three-quarter view, direction 104) live outside the repo in
`$ACR_SOURCES/generated/{tripo,meshy}/<Type>_sprite.glb` (Tripo preferred where both exist).
One four-line script per type calls `genbuild.building(ctx, TYPE, budget)` or
`genbuild.ship(ctx, TYPE, length, draft)`; the build needs the game folder, as the fit uses
the sprite reference.

- **Fit** (`acr_assets.spritefit`, pure numpy, `tests/test_spritefit.py`): the surface is sampled
  into 300k points; for every turn about +Z (10 degree steps; the best four refined) the
  points are projected through the original camera, and the uniform scale and ground shift
  that put them onto the sprite's silhouette are searched in screen space (an orthographic
  camera turns a scale into a 2D scale about the ground point, a shift on the ground into a
  2D shift). The score is the silhouette IoU, as `acr model-check` measures it. The lowest
  point stands at z = 0 and the ground point is the reference anchor, so the building's
  `LOCATION` offset is honoured; the footprint follows from the fitted scale (not from
  `LOCKPOINTS`).
- **Buildings** keep their base-colour texture (shrunk to 1024 px) and are collapse-decimated
  to 8k (houses, storehouses) or 12k triangles (town halls, churches, forts). They are one
  static mesh: no construction stages, sections, ruin or fire anchors (the renderer shows
  models for finished buildings only).
- **Ships** take the turn from the same fit against the direction-104 view, snap the long axis
  to Y (bow south), are scaled to a real `length` (the sprites are drawn smaller: the
  sprite fit's length is in stats as `sprite_length_m`) and sunk to `draft`; rig and clips
  as `ships.build`, without sail bones (the mesh is one piece).
- Types with a scripted model keep it; `GENERATED = True` in `incdo1.py`, `shppinta.py`,
  `shpsanta.py`, `shpfregat.py` builds the generated one instead.
- Stats: `source`, `source_triangles`, `triangles`, `fit` (yaw, scale, shift, raster IoU,
  the four best rough turns), `iou` (after decimation), `size_m`; ships also `length_m`,
  `draft_m`, `sprite_length_m`, `iou_sprite_scale`.
